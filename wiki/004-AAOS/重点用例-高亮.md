## SF 子系统

### TC_SF_FAULT_002 — AMS-WMS 死锁重现　🟡
- **意图**：[[system_server]] 高 [[Binder IPC|Binder]] 负载/[[ANR|ANR]] 时，[[SurfaceFlinger]] 不被连累。
- **为什么❤️**：AMS↔WMS 锁序死锁是历史高频；SF 若跟着挂 = 黑屏。
- **怎么测**：并发 dumpsys/am 轰炸 Binder → 监控 `ANR in`/WATCHDOG → 断言 SF pid 稳定 + 画面恢复。
- **TODO**：真实死锁需构造特定锁序竞争场景（当前仅施压暴露）。

### TC_SF_BOUND_002 — Producer 速率极限（反压）　🧩
- **意图**：Producer 30→1000fps，[[Buffer Queue]] 反压是否正确触发、producer 被阻塞。
- **为什么❤️**：反压失效 → buffer 溢出/内存爆。会议列为"思考反压路径"。
- **TODO**：需 native BufferQueue producer（`bq_producer`）。

### TC_SF_BOUND_003 — Consumer 速率极限　🧩
- **意图**：Consumer 极慢 → slots 耗尽 → dequeue 正确错误码、无死锁、fd 稳定。
- **TODO**：需 native 慢 consumer；已给 fd 泄漏监控骨架。

## HWC 子系统

### TC_HWC_FAULT_002 — 坏 Layer 参数　🧩
- **意图**：crop=(-1,-1)/transform=nan/alpha>255/非法 dataspace → [[HWC]] 拒绝且不 crash。
- **为什么❤️**：坏参数打崩 composer / 损坏 DPU 寄存器是硬件级风险。
- **TODO**：需 HWC HAL 非法参数注入 harness（LD_PRELOAD / `hwc_layer_fuzz`）。

### TC_HWC_FAULT_003 — 多屏 Layer 故障隔离　🧩
- **意图**：向 [[仪表（Cluster/a720）]] 提交非法 layer → IVI 不受波及。
- **为什么❤️**：一屏故障扩散到另一屏 = 功能安全问题。
- **TODO**：需 Cluster 侧注入 + 串口通道。

## GFWK 横向

### TC_GFWK_STRESS_001 — 低内存 + SF 压力　🟡
- **意图**：触发 LMK 低内存 + SF 高频操作 → SF 不 ANR、优雅降级。
- **为什么❤️**：低内存是实车高频场景（尤其 [[仪表（Cluster/a720）]] 内存紧张）。
- **怎么测**：`stress-ng --vm` 吃内存 + 快速 activity 切换 → 断言 [[SurfaceFlinger|SF]] 存活 + 画面恢复。
- **TODO**：仪表侧低内存优先覆盖需 a720 注入。

### TC_GFWK_STRESS_003 — dma-heap 碎片化 + 跨 SoC　🧩
- **意图**：[[dma-buf heap]] 碎片化后，跨 SoC 投屏申请大 buffer → 成功或 graceful fail。
- **为什么❤️**：碎片化 + 大块分配失败 → 投屏黑屏/driver crash。
- **TODO**：需 native 碎片化/大块分配工具 + [[composer_stub]] 跨 SoC 工装。
