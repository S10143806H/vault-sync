Lesson 01 · 指标 Metrics

一个「指标」到底是什么

3 个部件:数据源 → 度量 → 阈值判定。用你自己的 screen_not_black 拆开看。

本课一个赢: 学完你能拿起 gfwk 里任意一个判据,一眼说出它的 数据源 / 度量 / 阈值——这是把性能数据接进 kill SF 的前提。

① 定义:指标 = 可测量的量 + 判定规则

测试里的一个「指标」(metric)不是一个数,而是三个部件组成的一条判定链。缺任何一个都不成立:

1. 数据源 Source — 这个数从哪来? 截图像素?dumpsys?Prometheus?决定了实时性和可靠性。
2. 度量 Measure — 把原始数据压成一个可比的数。 如"亮像素占比 2.2%""GPU 45%"。这一步是降维:一张图 → 一个标量。
3. 阈值判定 Threshold + Verdict — 一条规则把数变成 通过/失败。 如 ratio >= 0.0005。没有阈值的数不是指标,只是日志。
核心心法:指标的价值不在"测到了数",在"数能自动变成判断"。 一个数据源如果没配阈值,它只是监控;配了阈值并 gate 结果,它才是判据。

② 拆你自己的代码:screen_not_black

这是你 common/Gpu/gfwk_stress_util.py 里正在用的判屏逻辑。三部件一一对上:

# 数据源:adb 截图 → 本地 png
aw.adb_shell(aw.dut.car0, f"screencap {dsel}-p {rp}")
aw.adb_pull(aw.dut.car0, rp, lp)

# 度量:一张图 → 一个标量(亮像素占比)
ratio = image_bright_ratio(lp)          # np.count_nonzero(gray>60)/gray.size

# 阈值 + 判定:标量 → True/False
ok = ratio >= min_bright_ratio          # 默认 0.0005 (0.05%)
部件在代码里是谁值示例
数据源screencap + adb_pull一张 PNG
度量image_bright_ratio()空调屏 2.2% / 纯黑 0%
阈值判定ratio >= 0.00052.2% → 非黑 ✓

为什么阈值是"亮像素占比"而不是"平均亮度":空调屏黑底+时钟,均亮≈4, 旧 mean<5 会误判黑;换成"有没有亮像素"就稳了。选对度量 = 指标成败的关键。

③ 两类指标:判据 vs 监控(这决定性能数据怎么接)

判据指标 assertion监控指标 telemetry
作用gate 用例 通过/失败只记录,看趋势
例子screen_not_blackFPS / GPU / 内存
失败时用例 FAIL写 log / 告警,不挂用例
要求阈值必须稳、误判率低先积累数据再定阈值
应用到你的目标
性能数据(sys_gpu_usage 等)因为有采集延迟 + DB 会抽风, 第一步应作「监控指标」:kill SF 后 snapshot 一次进 log。跑几轮确认数据靠谱、 波动范围清楚了,再升级成「判据指标」加阈值。—— 这正是上一轮我建议"先软监控"的原因, 现在你能用三部件语言解释为什么了。
