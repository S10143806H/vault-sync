# GFWK 稳定性测试 — 需求规格说明书 v2

> 关联概念：[[000-GFWK图形框架总览]] | 用例总表：[[重点用例-高亮]]

---

## 第一讲：显示系统的本质是什么问题

屏幕上的一帧，是**多个同学各画各的一块、拼成完整黑板**的结果。这套系统天然背着三座大山：

- **共享**：白纸（buffer）要在多方之间借来还去，同一张纸一秒被传递六十次
- **时序与组合**：谁先画谁后取差一微秒就是花屏
- **单点**：班长（[[SurfaceFlinger|SF]]）是唯一能贴黑板的人，他倒了全班停工

---

## 第二讲：五个角色，一条流水线

```
同学画稿 → 领白纸 → 放提交槽 → 班长拼版 → 挂墙工贴上黑板
(App)    (Gralloc) (BufferQueue) (SF)        (HWC/GPU)
```

| 教室角色 | 技术名 | 职责 | 常见问题 |
|---|---|---|---|
| 纸库房 | [[dma-buf heap]] | 所有白纸的真实存储（内核内存池） | 库存用尽/碎片化 → 领不到大纸 |
| 发纸员 | [[Gralloc]] | 按格式/尺寸发空白纸 | 挂了 → **冻屏**（不是黑屏），新帧无法分配，旧帧还在 |
| 提交槽 | [[Buffer Queue]] | 同学交纸（queue）、班长取纸（dequeue）的中间缓冲 | 槽满没人取 → 反压卡死；状态机防止同一槽被两人同时领 |
| 班长 | [[SurfaceFlinger\|SurfaceFlinger]] | 从槽取所有人的纸，按 z-order 拼版 | **黑屏**：班长一倒，画得再好也上不了黑板 |
| 挂墙工 | [[HWC]] | 用磁铁快速把拼版贴上黑板（硬件 overlay） | 层数/格式超限 → 回退 GPU；坏参数 → 拒绝但不崩 |
| 美术委员 | `GPU` | 挂墙工搞不定时手工慢慢画（软件合成） | 合成慢 → 掉帧；与 HWC 结果不一致 → 切换时颜色/透明度跳变 |
| "画完了"举牌 | [[Fence]] | 举牌后班长才能取，防拿到半成品 | 未举牌就取 → 花屏 / kernel panic（UAF） |
| 换纸铃 | [[VSync]] | 只在铃响时换黑板内容，防上下错位（tearing） | 供纸跟不上 → DPU underflow；超时 → flip_done timeout |
| 隔壁班黑板 | [[composer_stub]] | 把拼版送到另一颗 SoC 的仪表屏 | fence 跨核丢失 → 冻屏 / double-free |

> **关键区分**：`Fence` 管"这张纸画完没"（生产者→消费者时序）；`BufferQueue 状态机` 管"这个槽空没"（防止两个生产者同时领同一槽）。两件事，两个机制。

## 第三讲：从三座大山推导七条测试

### 大山一：共享的纸 → 泄漏类测试

发纸员发出去的纸必须还回来。如果同学一直借纸不还——三小时后纸库房空了，发纸员无纸可发，全班停工冻屏。这就是 **buffer / fd 泄漏**。

**度量方式**：不测"有没有"，测**增长曲线**。借还 10 万次，看库存是否持续下降。单次测不出慢性泄漏。

→ `TC_SF_BOUND_002`（槽位反压）、`TC_SF_BOUND_003`（fd 稳定性）

### 大山二：唯一的班长 → 恢复类测试

班级只有一个班长（[[SurfaceFlinger|SurfaceFlinger]]）。班长晕倒 → 黑板立刻全黑，不管同学画得多好。

> 问题不是"班长会不会晕" —— 他一定会（OOM / kill -9）。  
> 真正的问题：**晕倒后备用班长多快能顶上来？**

**度量方式**：主动打晕 180 次，测每次恢复时间 SLA（<10s）。1 轮只证明"不崩"；180 轮测的是**累积劣化**——恢复时间有没有越来越慢、fd 有没有一点点泄漏。

→ `TC_SF_FAULT_001`（kill SF 恢复）、`TC_SF_FAULT_002`（AMS/WMS 压力下 SF 不受波及）

走廊传递员（`composer_stub`，跨SoC）同样是单点 → `TC_HWC_FAULT_002`：断开 100 轮，检查每次重连时有没有把同一张纸还了两次（double-free）。

### 大山三：时序与参数组合 → 正确性类测试

**举牌（Fence）必须被遵守**：班长提前拿走没画完的纸：
- 轻则：贴上黑板是半成品 → 花屏
- 重则：内核认为这张纸已归还、又被别人借走正在写 → **同一张纸两个人同时用** → kernel panic（UAF = Use After Free）

**纸的规格组合**：格式 × 尺寸 × 用途有几十种，任何一种对齐（stride）算错就花屏。人工想不到所有组合，**只能穷举**。

**挂墙工 vs 美术委员一致性**：两者对同一张纸的处理结果（透明度、颜色混合）必须完全相同，否则切换瞬间画面跳变。

→ `TC_HWC_FAULT_002`（坏参数注入，验证拒绝不崩）、`TC_HWC_FAULT_003`（多屏隔离）

## 第四讲：测试流程为什么长这样

正常上课秩序井然，不会暴露 bug。稳定性测试必须：

1. **主动打晕班长**（不等他自己晕，`kill -9`）
2. **让同学疯狂交稿**（不按 30fps，而是 1000fps 塞满提交槽）
3. **给挂墙工非法指令**（`0xffffffff` 这种坏参数，看是优雅拒绝还是崩溃）
4. **用 Monkey 随机砸**（在最不巧的时刻触发故障，撞时序窗口）

> **正常流程 = 测已知路径。稳定性测试 = 故意踩坏边界**，看系统是正确失败（有保护）还是错误失败（崩溃/泄漏）。

## 第五讲：七条测试 = 三座大山的映射

| 大山 | 测试维度 | 度量方式 | 当前用例 |
|---|---|---|---|
| 共享→泄漏 | LEAK / BOUND | 增长曲线，不是单次 | [[TC_SF_BOUND_002]] / [[TC_SF_BOUND_003]] |
| 单点→恢复 | FAULT | 恢复时间 SLA，累积劣化 | [[TC_SF_FAULT_001]] / [[TC_SF_FAULT_002]] |
| 时序→正确性 | 参数覆盖 / fence 生命周期 | 覆盖率驱动，穷举 | [[TC_HWC_FAULT_002]] / [[TC_HWC_FAULT_003]] |

## 课后问题（供自测）

1. 发纸员（Gralloc）挂了，黑板会立刻全黑吗？（答：**冻屏**，不是黑屏——旧帧还在 DPU 里，只是新帧无法分配）
2. `Fence` 和 `BufferQueue 状态机` 各管什么？（答：Fence 管"这张纸画完没"；状态机管"这个槽空没"——两件事）
3. 挂墙工（HWC）和美术委员（GPU）结果不一致会怎样？什么时候切换？（答：切换瞬间颜色/透明度跳变；层数/格式超限时回退 GPU）
4. TC_SF_FAULT_001 为什么跑 180 轮而不是 1 轮？（答：测**累积劣化**——单次只证明不崩，多轮才能看出 fd 泄漏或恢复时间变慢）
5. 8 个槽全被班长持有时，同学 `dequeueBuffer` 会怎样？（答：**blocking 模式下挂起等待**，直到班长 release 一个槽；不崩溃、不立刻报错）
6. 班长拼版花了 20ms，超过 VSync 的 16.6ms，这帧会怎样？（答：DPU 在 VSync 时来取，新帧没好，**继续扫描上一帧**（重复显示）= jank；新帧延迟到下一个 VSync 周期）
7. `kill -9 SurfaceFlinger` 后为什么是**黑屏**而不是冻屏？（答：[[SurfaceFlinger|SF]] 消失 → 无人向 DPU 提交新 framebuffer → 显示管线断供 → 黑屏；对比 [[Gralloc]] 挂了：DPU 里最后一帧还有效，继续扫描 → 冻屏）
