# 座舱

用"一栋楼"来比喻：这颗座舱芯片是**一栋楼，里面住着好几户人家**——[[中控 Android（IVI）]]、[[仪表（Cluster/a720）]]、[[智驾（ADAS）]]、[[安全核|安全核（CP0/CP1）]]，平时各过各的日子。四个词就是四种"折腾这栋楼"的方式：

## 🔄 [[socreboot]] = 整栋楼拉闸重启
## 🚪 [[mainreboot]] = 只重启其中一户
## 😴 [[STR]] = 全楼睡觉，不是重启

## 📸 [[RAMdump]] = 出事后封锁现场取证

不是重启方式，是**破案机制**。系统死机时，普通重启会把内存清空——"案发现场"就没了，工程师无从查起。ramdump 的做法是：

1. 提前写入一个标记（就是那个 `ramdump_ctrl=0x5a5c0fa1`），告诉芯片"下次出事**别打扫现场**"
2. 死机后芯片重启到一个特殊小模式（U-Boot/fastboot，就是 a720 串口上那个 `5242000a`），**内存内容原封不动**
3. 台架用 `fastboot getvar ramdump-info` 把几个 GB 的内存整个"拓印"下来（[[RAMdump]]），工程师拿去离线分析死机瞬间每个变量的值

相当于**飞机黑匣子 + 案发现场拍照**。`test_015_ramdump` 测的就是"制造一次死机 → 确认能进取证模式 → 确认现场能拓印"。

## 一张表总结

| 操作             | 影响范围        | 内存       | 典型场景              |
| -------------- | ----------- | -------- | ----------------- |
| **socreboot**  | 整颗芯片所有域     | 清空       | 彻底复位、ramdump 配置生效 |
| **mainreboot** | 单个域（如仅 IVI） | 该域清空     | 单系统故障恢复，不连累仪表     |
| **STR**        | 全部睡眠、内存保电   | **保留**   | 锁车下电、解锁秒醒         |
| **ramdump**    | 死机后进取证模式    | **故意保留** | 抓死机现场给工程师破案       |

|用例|内容|
|---|---|
|`test_005_socreboot` / `socreboot_cp0`|整芯片复位（IVI 侧 / CP0 侧触发），重启后查全部串口 + 中控/仪表屏点亮|
|`test_005_mainreboot_ivi` / `adas` / `cp1`|**单域重启**——只重启一户，验证不连累邻居|
|`test_005_osreboot_3os`|三个 OS 一起 osreboot|
|`test_003_reboot_recovery`|进 recovery 模式再恢复|
|`test_004_reboot_bootloader`|进 fastboot（bootloader）模式，确认 `fastboot devices` 能枚举，再断电恢复——就是昨天连累下家的那个|
|`test_7_002_reboot_edl`|进 EDL（紧急下载/刷机模式）——刷机链路的前提|
|`exception_reboot/` 子目录|**异常重启**：`echo c` 触发 kernel panic（IVI/ADAS/Cluster 各一个）、WWDT2 看门狗超时复位（各一个）——验证"崩了能自己爬起来"|
