# 实车用例测试记录表单设计 v2

## 目标

承载
[Starry量产复杂用例-媒体](https://guatechltd.feishu.cn/wiki/Bo5Aw5Li5i2i3zkTO4gcINxbngg)
第 3 章「实车验证」的用例结果填报。v1 已上线，v2 解决填写者侧的重复劳动。

| 现存问题 | 根因 | v2 的处理 |
|---|---|---|
| 每条用例都要重填验证人/车辆/日期/版本 | 一次提交 = 一条用例，表单无跨次记忆 | 验证人与日期取系统字段；车辆与版本每天登记一次后由脚本回填 |
| 断续多天填报，填写者不知还剩几条 | 用例清单表无进度字段，无面向填写者的视图 | 清单表补 4 个进度字段 + 3 个进度视图 |
| 表单 8 题、6 项必填 | 上下文字段与结果字段混在一张表单 | 降到 4 题、2 项必填 |

填报节奏假设：**边测边填、断续多天、可能换人接手**。因此保留「一次提交 = 一条用例」，
不做「一次提交 = 一整轮」的长表单。

## 架构

```
多维表格「Starry 媒体用例集 · 测试记录」
├── 表 实车用例清单   24 条用例 + 进度字段；3 个进度视图
├── 表 测试记录·实车  4 个模块表单写入目标，一行 = 一次用例测试
└── 表 轮次登记       每人每天一行，存车辆信息与软件版本；1 个登记表单
```

## 填报流程

车上贴两个二维码：

| 序 | 入口 | 频次 | 题数 |
|---|---|---|---|
| ① | 今日登记 | 每人每天 1 次 | 3（车辆信息、软件版本、备注） |
| ② | 模块结果填报（4 个之一） | 每条用例 1 次 | 4（用例编号、测试结果、测试问题、拍照） |

填写者在 `① 待测清单` 视图随时看到本模块还剩哪些未测。

## 表单字段

`测试记录·实车` 共 14 个字段，其中只有 4 个对填写者可见。

| 字段 | 表单可见 | 必填 | 来源 |
|---|---|---|---|
| 用例编号·{模块} | 是 | 是 | 单选，各表单只显示本模块的那一列 |
| 用例测试结果 | 是 | 是 | 通过 / 失败 / 阻塞 / 未测 |
| 测试问题 | 是 | 否 | 字段说明提示「失败/阻塞/未测时填写」 |
| 用例拍照结果 | 是 | 否 | 附件，排最后 |
| 提交人 / 提交时间 | — | — | 系统字段，自动写入 |
| 验证人名字 / 测试日期 | 否 | — | `sync_progress.py` 从提交人与提交时间回填 |
| 车辆信息 / 验证软件版本 | 否 | — | `sync_progress.py` 从 `轮次登记` 按（提交人, 当天）回填 |
| 测试次数 | 否 | — | 不再提问；同一用例的执行次数以提交条数统计 |
| 本轮登记 | 否 | — | 关联字段，指向 `轮次登记` 中匹配的那一行，由脚本写入 |

## 关联与回填规则

两张表以**提交人**为关联键，按天细分：`轮次登记` 用 `(登记人 open_id, 登记日期 Asia/Shanghai)`
建索引，同键取最新一条；`测试记录·实车` 每行用 `(提交人 open_id, 提交日期)` 查表。命中后：

1. 写关联字段 `本轮登记`（type 18，单向单选），在界面上可直接点开当天的登记行；
2. 把 `车辆信息`、`验证软件版本` 复制进本行，**仅填补空字段，不覆盖已有值**，
   使历史记录保留提交当时的上下文，不随登记被改而漂移；
3. `验证人名字` 取 `提交人` 姓名，`测试日期` 取 `提交时间`。

查不到登记时该行留空，脚本输出「缺登记 N 行」。

### 前提：表单必须限企业内部填写

5 个表单的 `shared_limit` 均为 `tenant_editable`。若放开为 `anyone_editable`，
未登录填写者会被分配临时 guest open_id，**同一人换浏览器或隔天会拿到不同 id**，
关联键随之失效。实测已出现过 `Guest User 36312` 这种提交人。

## 进度回写

`实车用例清单` 增加 `表单选项文本`、`提交次数`、`最新结果`、`最新验证人`、`最新提交`。
匹配键为表单选项文本，构造规则：

```
车型 != "通用" 时： "{车型} · {用例编号} · {用例标题}"
否则：            "{用例编号} · {用例标题}"
```

该规则与 4 个单选字段的现有选项 24/24 完全一致，已实测校验。

## 防丢数据设计（v1 保留）

1. 附件非必填且排在最后，正文先落库。
2. 单次提交只有 4 题，弱网暴露窗口小。
3. 一次提交一条用例，可中断、可并行、可换人接手。

## 故障定位

| 观察 | 判断 | 操作 |
|---|---|---|
| 输出「缺登记 N 行」 | 该填写者当天没填 ① 今日登记 | 补登记后重跑脚本；已提交的结果不受影响 |
| `PATCH .../forms/{id}/fields` 报 `1254001` | 对已隐藏字段设 `required`，或同一请求同时传 `visible` 与 `required` | 先按当前状态清 `required`，再单独设 `visible`（`build_rcforms.py` 已这样处理） |
| 清单更新行数始终等于总数 | 表单选项文本与清单标签规则不符 | 比对单选字段选项与 `label_of()` 的输出 |
| `TableIdNotFound` | `base.json` 里的 table_id 已失效 | `GET /bitable/v1/apps/{token}/tables` 重新取，写回 `base.json` |
| 每次跑都报「回填 N 行」且 N 不变 | 关联字段读回的结构是 `[{"record_ids":[...]}]`，与写入的 `[record_id]` 不同形 | 用 `links()` 归一后再比较（已处理） |
| 提交人显示为 `Guest User xxxxx` | 表单被放开成 `anyone_editable` | 改回 `tenant_editable`，重跑 `build_rcforms.py` |

## 已知限制

- 车辆与版本按「同一人同一天只有一套」假设回填。一天内换车换版本需要当天补登记一次，
  且补登记之前提交的记录会带上旧值。
- 表单限企业内部填写，外部人员（供应商、候交付方）无法填报。
- 台架验证的三张表（`用例清单` / `测试记录` / `进度汇总`）已从 Base 中删除，
  本设计只覆盖实车 24 条。若恢复台架填报，需重建这三张表并扩展 `sync_progress.py`。
- `实车用例清单` 为 wiki 快照，文档更新后需重跑 `sync_rc_list.py`。
- 视图筛选与条件必填仍需界面手工配置，接口不支持。
